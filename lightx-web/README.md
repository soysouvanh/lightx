# LightX Web - The Full-Stack Dashboard (Tmplx)

Welcome to the pedagogical Web interface of the LightX framework. This project serves as an architectural showcase for both Front-end and Back-end development, exhaustively demonstrating how to utilize the exceptional rendering capabilities of the **Tmplx** engine (Zero-Allocation) coupled with the AOP routing of **LightX** and the data generation of **Daox**.

##  Quick Start (Step-by-Step Tutorial)

This guide is designed to showcase the full extent of rust SSR (Server-Side Rendering) architecture with State-of-the-Art performance.

### Step 1: Prepare the Development Environment

To run this project, make sure you have Rust installed:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

### Step 2: Run the Application (The Magic of the Build)

The absolute advantage of this showcase is that it uses **in-memory SQLite (sqlite::memory:)** and the _offline_ structures generated by Daox. There is absolutely nothing to install.

1. **Navigate to the `lightx-web` project directory:**

   ```bash
   cd lightx-web
   ```

2. **Launch the development compiler:**
   ```bash
   cargo run
   ```

>  **What is happening here?** During this command, the framework will:
>
> 1. Invoke the **Tmplx** compiler: It reads the `templates/` folder, mathematically verifies the syntax, and converts all your HTML code into pure Rust macros operating at `O(1)` speed without any dynamic allocation (0 heap bytes!).
> 2. Analyze the models and orchestrate the AOP of your `handlers/` routers.
> 3. Launch the powerful asynchronous web server on port `8081`.

### Step 3: Discover the Exhaustive Dashboard (Tmplx)

Congratulations, the server is running. Go to your browser and open `http://localhost:8081/dashboard`.

You will discover an ultra-powerful dashboard that demonstrates complete mastery of the variables and instructions of the **Tmplx** engine:

- **Variables and Escaping (Raw/Secure)**: `{%%= view_data.message %}` vs `{%= view_data.id %}`
- **Algorithmic Logic (Loops and Conditions)**: `{% for user in view_data.users %}` and `{% if user.is_admin %}`
- **Modular HTML Architecture**: The root Layout via `extends`, dynamic blocks via `block`, and reusable partial models via `include`.
- **CRUD API Methodology**: The View, Add, and Edit pages chain together instantly to prove that you can mix LightX AOP (Handlers) without any editorial fatigue!

##  Architecture and Foundations of Rust SSR

### The "Duck-Typing" Approach of the Tmplx Compiler

Where does the feat of `lightx-web` lie in comparison to the rest of the Rust web ecosystem? In the constraint of the View Models!
Here, if you rename the property `pseudo` to `name` in your `dashboard.rs` Business Object, **the compilation of your HTML pages will instantly fail and stop!**

Thanks to `Tmplx` included via your `build.rs`, your HTML is not a lost text file. It becomes an AST (Abstract Syntax Tree) and strictly asks the `rustc` compiler to certify that _all variables invoked_ in the DOM actually exist on the structures returned by the BO before accepting the deployment. This is the absolute quality assurance.
